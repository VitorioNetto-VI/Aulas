Módulo 1 — Fundamentos

O que é Arquitetura de Software?

A arquitetura de software é a estrutura fundamental de um sistema, definindo seus componentes, suas relações e os princípios que guiam seu design e evolução.

💡
Analogia: Pense na arquitetura de software como a planta de um edifício. Antes de construir, você decide quantos andares terá, onde ficam as escadas, como a água e a energia serão distribuídas. A arquitetura define essas decisões fundamentais antes da implementação.

🧩 Componentes

Partes individuais do sistema que executam funções específicas.

🔗 Conexões

Interações e comunicação entre os componentes do sistema.

📐 Princípios

Regras e restrições que guiam o design e a evolução.

Módulo 1 — Fundamentos

Abordagens de Desenvolvimento

Model-Driven Architecture (MDA)

Abordagem que utiliza modelos para definir a estrutura e comportamento do software antes da implementação.

Modelo em três camadas:

📱 Apresentação

Interface com o usuário, telas e formulários.

⚙️ Lógica de Negócio

Regras, validações e processamento central.

💾 Dados

Persistência, bancos de dados e armazenamento.

Model-View-Controller (MVC)

Padrão que separa a aplicação em três componentes interconectados:

📦 Model

Representa os dados e a lógica de negócio. É a "fonte da verdade" da aplicação.

👁️ View

Interface visual que apresenta os dados ao usuário de forma formatada.

🎮 Controller

Recebe entradas do usuário, processa e atualiza Model e View.

Service-Oriented Architecture (SOA)

Princípios de serviços independentes que se comunicam através de protocolos padronizados.

🔑
Princípio-chave: Cada serviço é autônomo, possui uma interface bem definida e pode ser consumido por diferentes aplicações. É o precursor conceitual dos microservices.

Módulo 2 — Estilos Arquiteturais

Arquitetura Monolítica

Definição: Sistema único e indivisível, onde todos os componentes fazem parte de uma única unidade deployável.

📜
História: Surgiu como abordagem padrão nas primeiras décadas da computação. A simplicidade e unificação de um único código-fonte facilitavam desenvolvimento e implantação. Ainda é amplamente usada em aplicações web tradicionais e sistemas ERP.

❌ Desvantagens

  • Dificuldade de escalabilidade

  • Risco de falha única afetar tudo
  • Deploy requer reinício total

Arquitetura de Microservices

Definição: Conjunto de serviços pequenos e independentes, cada um executando um processo específico e comunicando-se por mecanismos leves.

📜
História: Ganhou popularidade na última década como resposta aos desafios de escalabilidade do monolito. Empresas como Netflix e Amazon adotaram essa abordagem para permitir escalabilidade horizontal e independência de desenvolvimento.

Módulo 2 — Estilos Arquiteturais

Arquitetura Event-Driven

Definição: Baseada em eventos para comunicação assíncrona entre componentes. Os sistemas reagem a eventos conforme eles ocorrem.

📜
Contexto: Surgiu como solução para sistemas que exigem alta flexibilidade e resposta rápida. Utilizada em processamento de dados em tempo real e aplicações de IoT, permitindo comunicação assíncrona e escalabilidade sem interrupções.

Módulo 4 — Aplicação

🏆 Desafios Práticos

Atividades para aplicar os conceitos em cenários reais.

Desafio 1: Análise de Cenário

Uma startup de food delivery precisa escolher sua arquitetura. Ela tem: 5 devs, orçamento limitado, previsão de crescimento de 10x em 6 meses.

  • Identificar o estilo arquitetural mais adequado para o momento atual
  • Justificar a escolha com pelo menos 3 argumentos
  • Propor uma estratégia de evolução para o futuro
  • Apresentar riscos da escolha e mitigação

Desafio 2: Decomposição de Monolito

Dado um sistema ERP monolítico com módulos de RH, Financeiro, Estoque e Vendas, proponha uma estratégia de migração para microservices.

  • Definir a ordem de extração dos serviços
  • Identificar dependências entre módulos
  • Propor estratégia de comunicação entre serviços
  • Estimar impactos no time de desenvolvimento

Desafio 3: Design Event-Driven

Projete um sistema de notificações para uma plataforma de streaming que precisa processar eventos de: play, pause, seek, buffer e complete.

  • Definir os produtores e consumidores de eventos
  • Especificar o formato dos eventos
  • Propor estratégia de garantia de entrega
  • Desenhar o fluxo de pelo menos 2 cenários
Módulo 4 — Aprofundamento

🔬 Tópicos Avançados

Conceitos que complementam e aprofundam o conhecimento em arquitetura de software.

🐳 Containers e Orquestração

▼

Docker e Kubernetes revolucionaram a implementação de microservices, permitindo deploy isolado, escalabilidade automática e gerenciamento simplificado de centenas de serviços.

Infraestrutura

🔄 API Gateway e Service Mesh

▼

Padrões essenciais para gerenciar comunicação em arquiteturas distribuídas. API Gateway centraliza autenticação, rate limiting e roteamento. Service Mesh (Istio, Linkerd) gerencia comunicação service-to-service com observabilidade.

Comunicação

📊 Observabilidade Distribuída

▼

Em sistemas distribuídos, monitoramento tradicional não é suficiente. É necessário implementar os três pilares: Logs (centralizados), Métricas (Prometheus/Grafana) e Traces (distributed tracing com Jaeger/Zipkin).

Monitoramento

🏗️ Domain-Driven Design (DDD)

▼

Abordagem que alinha a arquitetura ao domínio de negócio. Conceitos-chave: Bounded Contexts, Aggregates, Entities, Value Objects. Essencial para definir boundaries corretos em microservices.

Design

⚡ Event Sourcing e CQRS

▼

Event Sourcing: Armazenar estado como sequência de eventos, não como estado atual. CQRS: Separar modelos de leitura e escrita. Juntos, oferecem auditabilidade completa e performance otimizada.

📋 Resumo e Próximos Passos

Recapitulação dos conceitos fundamentais e direcionamento para continuidade do aprendizado.

O que aprendemos:

  • 📘 Fundamentos: Arquitetura define componentes, conexões e princípios de um sistema
  • 🏢 Monolítica: Simples no início, desafia na escala — ideal para MVPs e equipes pequenas
  • 🔌 Microservices: Escalável e resiliente, mas complexo — para sistemas maduros com múltiplas equipes
  • 📨 Event-Driven: Assíncrono e flexível — para tempo real, IoT e alto desacoplamento
  • ⚖️ Decisão: Não existe "melhor" arquitetura — existe a mais adequada para cada contexto
🚀
Próximos passos recomendados:
• Pratique decompondo um sistema monolítico em serviços
• Implemente um pequeno sistema event-driven com RabbitMQ ou Kafka
• Estude Domain-Driven Design para melhorar definição de boundaries
• Explore Kubernetes para orquestração de containers
